# Feature Specification: DiskANN Post-GlobalGraph Search Evaluation

**Feature Branch**: `feature/search-evaluation`

**Created**: 2026-08-18

**Status**: Draft

**Input**: Build reusable DiskANN post-graph disk-search assets from validated Dataset and
GlobalGraph inputs, execute and observe pinned DiskANN disk search, and evaluate the resulting raw
observations without rerunning graph construction.

## Reproduction and Experiment Governance *(mandatory)*

**Study Class**: `infrastructure_validation` for the MVP capability and parity gate. A later formal
evaluation MUST also retain the study class and implementation identity of the evaluated
GlobalGraph and MUST NOT relabel a Baseline, single-paper result, or cross-paper comparison.

**Baseline Reference**:

```yaml
repository: https://github.com/microsoft/DiskANN.git
branch: cpp_main
commit: 78256bbab4685e1774e78d331e081a153be26823
source_path: upstream/diskann-cpp-main
```

The fixed source is the authority for post-graph disk layout, `PQFlashIndex` load/search,
`QueryStats`, Recall, QPS, latency, Mean IOs, and canonical timing semantics.

**Replacement Scope**: None of Partition, Local Build, or Merge is replaced. This is an independent
downstream feature beginning with an already validated `DatasetArtifact` and
`GlobalGraphArtifact`. It MUST NOT become a fourth `PipelineExecutor` stage.

**Reproduction Modes and Implementation Identities**:

- `upstream_faithful`: the pinned, unmodified DiskANN `search_disk_index` behavior is the search,
  result, metric-semantic, and timing-boundary oracle.
- `instrumented`: a distinct project-owned thin runner invokes the same search path and preserves
  structured raw observations. Its stable implementation identity MUST differ from the oracle.
- Instrumented performance evidence is non-formal until the Search Runner Parity gate passes;
  Recall is governed independently by quality eligibility and does not certify Search Semantics,
  Quality Parity, or the final Baseline.

**ID-Space Contract**: The input graph and all returned neighbor identities use the complete
Dataset `GlobalNodeId` space. No `LocalNodeId`, unresolved replica identity, out-of-range result, or
modified node identity may enter a disk-search asset or observation.

**Artifact Flow**:

```text
validated DatasetArtifact + validated GlobalGraphArtifact
  -> PQArtifact + DiskLayoutArtifact
  -> SearchObservation/v1 from immutable QuerySet + SearchProtocol.search_execution
  -> SearchEvaluationReport/v1 from complete SearchObservation + immutable GroundTruth
```

`PQArtifact` and `DiskLayoutArtifact` are reusable immutable data products. Each generation has a
separate `BuildManifest`; each reusable product has separate validation evidence.
`SearchObservation/v1` and `SearchEvaluationReport/v1` are Feature-local versioned evidence and
MUST NOT be registered as new public Artifact families in the MVP. Artifact, BuildManifest,
ValidationEvidence, raw observation, and evaluation report remain separate objects and references.

**Validation Gate**: Every reused Dataset/GlobalGraph and every generated PQ/DiskLayout input MUST
be freshly validated for its declared type, version, checksum, ID space, capabilities, lineage, and
source-verified post-graph compatibility before downstream use. Complete observation validation is
required before evaluation. GroundTruth compatibility is checked only at evaluation and never
authorizes or changes search execution.

**Experiment Protocol**: MVP scale is at most SIFT1M, metric L2, full-precision disk vectors,
`PQ_disk_bytes=0`, reorder disabled, filtering disabled, range search disabled, and explicit
positive beamwidth with first-phase default `W=2`. Zero-cache and one fixed-cache condition are
separate immutable protocols. Only an ordered `L_search` list may vary within a protocol; thread,
beamwidth, cache, IO, warmup, timing, query order, and environment controls remain fixed. Every
repetition is retained and evaluated under a predeclared aggregation rule. There is no parameter
sweep, automatic tuning, changed-configuration retry, best-result selection, or execution above
SIFT1M. The first formal QuerySet is the repository's existing
`sift1M_dataset/selected_query.csv`, bound by immutable identity and checksum; its formal
GroundTruth MUST be generated by exact L2 evaluation against the admitted SIFT1M Dataset identity.
Formal search execution uses `K=100`, retains all ordered top-100 results, requires GroundTruth
width at least 100 and `L_search >= 100`, and reports Recall@10 and Recall@100 as distinct metrics;
QPS and latency remain labeled as measurements of the K=100 execution. The first-phase entry policy
is end-to-end: every GlobalGraph uses its own declared and source-verifiable
entry/medoid/centroid lineage, including in any optional multi-GlobalGraph comparison. Every
declared search point executes three independent repetitions; all raw repetitions and failures are
retained, and formal cross-repetition summaries use the median of eligible repetitions under a
predeclared exclusion policy without replacement runs.

## Clarifications

### Session 2026-08-18

- Q: Which QuerySet/GroundTruth source is used for the first formal evaluation? → A: Use the
  existing `selected_query` as the only first-phase formal QuerySet and generate exact L2
  GroundTruth against the current SIFT1M Dataset.
- Q: How does `selected_query.id` affect Dataset self-match handling? → A: It is an opaque
  `source_query_id` from the query file, not the current CSV row ordinal, a Dataset row, or a
  GlobalNodeId. The zero-based `query_row_index` after the header is the canonical query identity
  and row-alignment key. Formal GroundTruth and Recall preserve but do not interpret
  `source_query_id` and perform no Dataset self-exclusion based on it.
- Q: What result K and Recall targets are used in the first formal search? → A: Search with
  `K=100`, retain top-100, and report Recall@10 and Recall@100 separately from the same observation;
  all L values are at least 100.
- Q: Which entry/medoid policy governs formal single-graph and optional multi-graph evaluation? →
  A: End-to-end; every GlobalGraph uses its own declared and traceable entry/medoid/centroid policy.
- Q: How many repetitions does each formal search point use, and how are they aggregated? → A:
  Run three independent repetitions, retain every raw result/failure, and report the median across
  repetitions eligible under the predeclared exclusion policy.

### Correction 2026-08-19

- Repository inspection established that the 4,885 query records contain unique, increasing CSV
  `id` values spanning 0 through 9,999 rather than current-file row ordinals. This correction
  replaces the earlier row-ordinal interpretation without assigning any otherwise unproven source
  semantics to the field.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Materialize a Searchable Disk Index (Priority: P1)

As an experiment framework user, I want to turn one validated Dataset and one validated
GlobalGraph into reusable PQ and disk-layout assets so that an existing graph can enter the pinned
DiskANN SSD-search path without rebuilding or changing that graph.

**Why this priority**: Search cannot be executed or evaluated until a validated graph has a
loadable, lineage-bound disk representation. This story independently establishes that downstream
boundary while protecting the expensive upstream graph result.

**Independent Test**: Use a small validated DatasetArtifact and GlobalGraphArtifact, materialize
their post-graph search assets, validate both outputs, load them through the pinned search path, and
prove that no Partition, Local Build, Merge, or graph mutation occurred.

**Acceptance Scenarios**:

1. **Given** a compatible validated Dataset and GlobalGraph, **When** post-graph materialization
   succeeds, **Then** independently stored PQ and DiskLayout products validate and the disk-search
   index can load them.
2. **Given** a successful materialization, **When** input and output evidence is audited, **Then**
   the GlobalGraph checksum is unchanged and the DiskLayout binds exactly that graph identity.
3. **Given** an invalid, incompatible, or unvalidated input, **When** materialization is requested,
   **Then** it fails before normal output publication and retains failure provenance without
   invoking Partition, Local Build, or Merge.
4. **Given** two explicit GlobalGraph comparison arms over the same Dataset, **When** their search
   assets are admitted, **Then** both arms use one byte-identical PQArtifact while each graph has
   its own DiskLayoutArtifact and its own declared, lineage-validated entry/medoid/centroid policy.

---

### User Story 2 - Execute and Evaluate Disk Search (Priority: P2)

As an experiment framework user, I want to execute the real pinned DiskANN disk-search path over
validated search assets, preserve complete per-query observations, and evaluate those observations
under a frozen protocol so that Recall, QPS, latency, and IO findings are reproducible without
mixing generation, execution, and evaluation evidence.

**Why this priority**: The scientific value of the Feature is a trustworthy raw search record and
an independently reproducible evaluation. It depends only on already materialized assets and can
be tested without rerunning User Story 1.

**Independent Test**: Use prebuilt validated PQ and DiskLayout fixtures plus immutable QuerySet,
GroundTruth, and SearchProtocol fixtures. Execute the instrumented disk search, preserve every
declared raw search point and query, then generate a separate SearchEvaluationReport from the raw
observation and GroundTruth.

**Acceptance Scenarios**:

1. **Given** valid search assets and a frozen search-execution declaration, **When** disk search
   completes, **Then** every declared `(L_search, repetition_index)` point retains all query result
   IDs, distances, required QueryStats, and its own canonical batch timing.
2. **Given** a complete compatible SearchObservation and GroundTruth, **When** evaluation runs,
   **Then** `quality_eligible=true` produces formal Recall@10 and Recall@100, while
   `performance_eligible=true` produces formal QPS, mean latency, P99.9 latency, and Mean IOs for
   the K=100 execution using pinned DiskANN semantics. For every complete successful
   quality-eligible observation, the existing Python Harness `evaluate` operation also computes and
   displays QPS, mean latency, P99.9 latency, and Mean IOs from the retained raw facts. When
   `performance_eligible=false`, persistence of those displayed values in SearchEvaluationReport is
   optional; if persisted, they are `informational_non_formal`, record the exclusion reason, and do
   not enter a formal performance aggregate.
3. **Given** unchanged search execution and raw observations but a changed compatible evaluation
   declaration, **When** a new evaluation is requested, **Then** a new report can be produced
   without repeating SSD search.
4. **Given** a failed, invalid, cancelled, identity-mismatched, or otherwise excluded raw
   observation, **When** evaluation is requested, **Then** its identity, path, checksum, terminal
   status, and exclusion reason are retained in the SearchEvaluationReport as audit/exclusion
   references only; it contributes no metric, aggregate, median, or comparison finding and cannot
   be quality-eligible or performance-eligible.
5. **Given** an environment that cannot establish the declared Linux/local-SSD IO semantics,
   **When** search completes for functional validation, **Then** its results cannot be labeled as
   formal QPS, latency, or IO evidence, while compatible complete observations may still produce
   formal Recall@10/Recall@100 through the separate quality-eligibility decision.
6. **Given** the first formal evaluation, **When** QuerySet and GroundTruth admission runs, **Then**
   the immutable QuerySet is `sift1M_dataset/selected_query.csv` and its GroundTruth is an exact L2
   result over the admitted SIFT1M Dataset identity rather than an unrelated public benchmark file.
7. **Given** a `selected_query` record, **When** QuerySet admission, GroundTruth, search observation,
   or Recall processing runs, **Then** its zero-based `query_row_index` is used for identity and row
   alignment, while the CSV `id` is preserved only as an opaque `source_query_id` and is never
   interpreted as a Dataset GlobalNodeId for self-match exclusion.
8. **Given** a formal single-graph run or optional multi-graph comparison, **When** results are
   reported, **Then** the report labels the entry policy as end-to-end and traces each arm to that
   graph's own entry/medoid/centroid lineage.
9. **Given** one declared L value and cache protocol, **When** formal search executes, **Then**
   exactly three independently identified repetitions are attempted and retained, and evaluation
   reports their individual metrics plus the median of eligible repetitions without adding a
   replacement run after observing a failure or result.

### Edge Cases

- A Dataset or GlobalGraph has an unsupported format, stale checksum, incompatible identity, wrong
  metric, invalid ID space, missing capability, or point count above SIFT1M.
- A GlobalGraph is structurally valid but lacks a source-verified native payload or entry/medoid
  condition required by the pinned post-graph path.
- A PQ payload, compressed-vector payload, disk layout, medoid, or entry metadata is missing,
  truncated, unparsable, or checksum-mismatched.
- A centroid payload is absent and the pinned source does not establish a compatible fallback.
- A DiskLayout or comparison silently substitutes a shared/controlled entry for a GlobalGraph's
  own declared entry/medoid/centroid policy or fails to label the result as end-to-end.
- A QuerySet or GroundTruth file is missing, changes byte length/checksum, has the wrong dimension,
  or is incompatible with Dataset, metric, K, or declared width.
- A file presented as first-phase formal GroundTruth was not generated by exact L2 evaluation of
  the admitted `selected_query` against the admitted SIFT1M Dataset identity.
- A QuerySet converter, GroundTruth generator, search runner, or evaluator uses
  `selected_query.id` instead of zero-based `query_row_index` for row alignment, treats that
  `source_query_id` as a Dataset GlobalNodeId, or removes a Dataset neighbor solely because its
  numeric value matches that field.
- An ordered `L_search` entry is invalid, beamwidth is not positive, cache policy changes inside a
  timed execution, or observed effective controls differ from the frozen protocol.
- A formal protocol declares `K` other than 100, an L value below 100, GroundTruth width below 100,
  or a completed query with other than 100 ordered results.
- A repetition or search point is missing, duplicated, overwritten, partially completed, or merged
  with timing/queries from another `L_search`, repetition, cache policy, or execution identity.
- A formal protocol requests other than three repetitions, aggregates them with a non-median rule,
  silently excludes an eligible repetition, or adds a replacement repetition after observing a
  failed, invalid, slow, low-Recall, or low-QPS outcome.
- A query has fewer than K results, duplicated or out-of-range result IDs where prohibited,
  non-finite distances, missing `total_us`, or missing `n_ios`.
- GroundTruth changes after a complete search observation exists: raw search remains reusable, but
  the old evaluation identity cannot authorize a new report.
- Search terminates, fails, or is cancelled after producing partial raw evidence: no reusable
  successful observation or report may be claimed.
- Upstream-faithful and instrumented results disagree on ordered IDs, tolerated distances, Recall,
  Mean IOs semantics, formulas, or timing boundary.
- A formal-performance run occurs on macOS, Docker-on-macOS, remote/network storage, or an
  environment whose local-SSD IO semantics cannot be established.
- A multi-GlobalGraph comparison uses different PQ data, QuerySet, GroundTruth, search controls,
  environment, or silently drops a failed/slow repetition.

## Requirements *(mandatory)*

### Functional Requirements

#### Scope, identity, and admission

- **FR-001**: The Feature MUST begin from freshly validated DatasetArtifact and
  GlobalGraphArtifact references and MUST reject incompatible type, version, checksum, capability,
  ID-space, lineage, metric, scale, or native post-graph conditions before materialization.
- **FR-002**: The Feature MUST operate strictly downstream of GlobalGraph production and MUST NOT
  add a fourth Partition/Local Build/Merge pipeline stage.
- **FR-003**: The Feature MUST NOT execute Partition, Local Build, or Merge; rebuild, refine, prune,
  repair, or replace the GlobalGraph; or alter its adjacency or GlobalNodeId values.
- **FR-004**: The Feature MUST retain verifiable evidence that Partition, Local Build, and Merge
  were not re-executed, using existing evidence mechanisms selected during planning rather than a
  new instrumentation framework.
- **FR-005**: MVP admission MUST be limited to datasets no larger than SIFT1M, L2 distance, and
  source-verified scalar and native graph formats compatible with the pinned post-graph path.
- **FR-006**: The fixed DiskANN source tree MUST remain read-only and clean; all builds, wrappers,
  evidence, experiments, and generated outputs MUST remain outside `upstream/`.
- **FR-007**: Upstream-faithful and instrumented search MUST use distinct reproduction modes and
  implementation identities, and instrumented evidence MUST NOT support formal performance claims
  before parity passes.
- **FR-008**: The MVP MUST use one explicit Feature execution path and MUST NOT introduce a public
  search-stage interface, search Registry/backend hierarchy, generic DAG/retry/comparison engine,
  or metric plugin system.

#### PQ and disk-layout products

- **FR-009**: Materialization MUST produce an immutable PQArtifact derived solely from the
  Dataset, independent of any particular GlobalGraph.
- **FR-010**: PQArtifact identity MUST bind the Dataset identity/checksum, L2 metric, point count,
  dimension, scalar type, PQ settings, pivots and compressed-vector payload identities, fixed
  DiskANN source identity, generation parameters, and aggregate checksum.
- **FR-011**: PQArtifact payload, BuildManifest, and ValidationEvidence MUST remain separate stored
  objects, and normal publication MUST require complete validation of required payloads, native
  format, dimensions, counts, and checksums.
- **FR-012**: An explicit multi-GlobalGraph comparison MUST reuse the exact same PQArtifact
  identity, aggregate checksum, and payload checksums across all comparison arms.
- **FR-013**: Materialization MUST produce one immutable DiskLayoutArtifact for exactly one
  DatasetArtifact and one GlobalGraphArtifact identity.
- **FR-014**: DiskLayoutArtifact identity MUST bind Dataset and GlobalGraph identities/checksums,
  GlobalNodeId space, point count, dimension, scalar type, L2 metric, full-precision disk-vector
  policy, `PQ_disk_bytes=0`, `reorder=false`, native payload identity, entry/medoid lineage, actual
  source-verified centroid policy, fixed DiskANN source identity, materialization parameters, and
  aggregate checksum. Its entry/medoid/centroid lineage MUST belong to that input GlobalGraph under
  the end-to-end policy.
- **FR-015**: DiskLayout materialization MUST preserve the input graph structure and MUST NOT alter
  adjacency, identity, degree semantics, or navigation semantics.
- **FR-016**: Any medoid, entry, centroid, or fallback policy used by DiskLayout MUST be supported
  by the pinned source and recorded with complete lineage; no project-invented navigation policy is
  permitted. The MVP MUST NOT replace it with a shared controlled-entry input.
- **FR-017**: DiskLayoutArtifact payload, BuildManifest, and ValidationEvidence MUST remain separate
  stored objects, and normal publication MUST require native format, lineage, count, dimension,
  checksum, entry/medoid, and loadability validation.
- **FR-018**: A failed, invalid, or cancelled materialization MUST retain its manifest, logs, and
  available diagnostic evidence but MUST NOT publish a reusable normal PQArtifact or
  DiskLayoutArtifact.
- **FR-019**: A successful materialization MUST demonstrate that the pinned DiskANN disk-search
  path can load the declared PQ and disk-layout assets.

#### Immutable inputs and SearchProtocol

- **FR-020**: QuerySet and GroundTruth MUST remain immutable checksum-bound input references in the
  MVP and MUST NOT create new public Artifact types. The first formal QuerySet MUST be the existing
  `sift1M_dataset/selected_query.csv`; no standard public SIFT1M QuerySet may silently substitute
  for it in the same protocol.
- **FR-021**: A QuerySet reference MUST bind logical location, format, byte length, SHA-256, query
  count, and dimension; a GroundTruth reference MUST additionally bind its declared width and MUST
  attest that it was generated by exact L2 evaluation of the admitted QuerySet against the admitted
  SIFT1M Dataset identity. Each query's canonical identity and GroundTruth/observation alignment key
  MUST be its zero-based `query_row_index` after the CSV header. `selected_query.id` MUST be
  preserved separately as an opaque `source_query_id`; it is not the current CSV row ordinal and
  MUST NOT be interpreted as a Dataset row or GlobalNodeId.
- **FR-022**: SearchProtocol MUST be a versioned, immutable, checksum-bound experiment declaration,
  separate from public Artifact publication, and MUST be frozen before formal execution.
- **FR-023**: SearchProtocol MUST separate `search_execution` from `evaluation` and provide an
  independently canonicalized identity/checksum for `search_execution`.
- **FR-024**: `search_execution` MUST bind Dataset, PQ, DiskLayout, QuerySet, L2 metric, fixed
  `K=100`, ordered `L_search` values each at least 100, positive beamwidth, thread count, cache
  mode/budget, IO limit, warmup, query order, timing boundary, storage placement, fixed repetition
  count 3, required performance environment, and the fixed `end_to_end` entry-policy
  classification.
- **FR-025**: `evaluation` MUST bind the exact-L2 GroundTruth for the admitted `selected_query`,
  with width at least 100, plus Recall/evaluator semantic version, separate quality/performance
  eligibility policies, and aggregation policy without participating in search execution.
- **FR-026**: GroundTruth MUST NOT be loaded or used by the `PQFlashIndex` search execution path and
  MUST only participate after a SearchObservation exists.
- **FR-027**: Any change to QuerySet, K, search controls, ordered `L_search`, or repetition count
  MUST create a new search-execution identity/checksum and require the declared search executions.
- **FR-028**: A change limited to GroundTruth, compatible evaluator semantics, exclusion policy, or
  aggregation policy MUST create a new evaluation identity but MAY reuse a complete compatible
  SearchObservation without rerunning SSD search.
- **FR-029**: The only MVP search-point list MUST be ordered `L_search`; the Feature MUST NOT expose
  a generic multidimensional sweep, optimization, early stop, or best-config selector.
- **FR-030**: Beamwidth MUST be an explicit positive value with first-phase default `W=2`;
  automatic beamwidth optimization is prohibited.
- **FR-031**: Zero-cache and fixed-cache MUST be declared and executed as separate SearchProtocols,
  and cache policy MUST NOT change inside one timed execution.
- **FR-032**: Within one SearchProtocol, beamwidth, thread count, cache policy, IO limit, warmup,
  query order, timing boundary, storage placement, and performance environment MUST remain fixed.
- **FR-033**: Each cache-specific protocol containing `n` ordered L values MUST attempt and preserve
  exactly `n * 3` independently identified raw search points, including retained terminal failures;
  failure or invalidity changes evaluation eligibility, not the declared attempt count.
- **FR-034**: Search points from different L values, repetitions, cache policies, or
  search-execution identities MUST NOT be averaged, overwritten, or combined during raw
  observation capture.
- **FR-035**: Formal execution MUST NOT use automatic retry or changed-configuration retry; every
  declared run, failure, invalid result, and exclusion MUST be retained under its immutable
  protocol and predeclared policy. No result-dependent fourth or replacement repetition is
  permitted.

#### SearchObservation and timing

- **FR-036**: The Feature MUST retain a versioned immutable `SearchObservation/v1` as Feature-local
  raw evidence rather than a public Artifact or generic observation framework.
- **FR-037**: Each SearchObservation MUST bind its observation/run and implementation identities,
  reproduction mode, SearchProtocol reference/identity, search-execution identity/checksum,
  PQArtifact, DiskLayoutArtifact, QuerySet identity/checksum, and complete source/build identity.
- **FR-038**: Every raw search point MUST record L, effective beamwidth, cache mode and effective
  cache state, repetition index, declared/completed query counts, canonical batch wall-clock time,
  and terminal status.
- **FR-039**: Every completed query MUST retain its zero-based `query_row_index` as query identity,
  the corresponding opaque `source_query_id`, ordered result GlobalNodeIds, ordered result
  distances, `QueryStats.total_us`, and `QueryStats.n_ios`; formal K=100 execution MUST retain
  exactly 100 ordered IDs and 100 corresponding distances per query.
- **FR-040**: Other pinned QueryStats fields MAY be retained when directly observable without
  semantic change but MUST remain optional in v1.
- **FR-041**: The real pinned disk search and necessary in-memory result/QueryStats capture MUST be
  inside the canonical batch timing boundary, while serialization, file writes, checksums,
  manifests, reports, evaluation, and debug persistence MUST remain outside it.
- **FR-042**: A successful search point MUST contain every declared query and exactly the required
  top-100 result data; partial, missing, wrong-count, duplicate, out-of-range, non-finite,
  identity-mismatched, or incomplete core QueryStats evidence MUST make it invalid for formal
  evaluation.
- **FR-043**: Failed, invalid, cancelled, identity-mismatched, or otherwise excluded raw evidence
  MUST be retained, and SearchEvaluationReport MUST preserve its observation identity, path,
  checksum, terminal status, and exclusion reason as audit/exclusion references. Such references
  are diagnostic only: they MUST NOT contribute Recall, QPS, latency, IO, any formal metric,
  aggregate, median, or comparison finding, and MUST NOT be marked `quality_eligible` or
  `performance_eligible`.
- **FR-044**: GroundTruth mismatch MUST NOT retroactively invalidate an otherwise complete raw
  search observation, but MUST block evaluation with that GroundTruth.
- **FR-045**: When a newly requested metric requires raw information absent from the retained
  SearchObservation, the system MUST declare that a new search execution is required rather than
  infer the metric from unrelated aggregates.

#### Evaluation and metric semantics

- **FR-046**: Evaluation MUST use the pinned DiskANN Recall matching, equal-distance tie, and
  numeric semantics; a semantically different Recall implementation is prohibited. Because the
  formal QuerySet provides no reliable Dataset GlobalNodeId mapping, GroundTruth and Recall MUST
  align queries by zero-based `query_row_index` and MUST NOT perform ID-based self-match exclusion
  using the opaque `source_query_id` from `selected_query.id`. Recall@10 and Recall@100 MUST be
  derived and labeled as two distinct metrics from the same complete top-100 observation.
- **FR-047**: Per-point QPS MUST equal completed query count divided by canonical batch wall-clock
  seconds and MUST NOT be inferred from summed or averaged per-query latency.
- **FR-048**: Mean latency MUST be the mean of per-query `total_us`, and P99.9 latency MUST match
  pinned DiskANN percentile semantics or proven-equivalent parity semantics.
- **FR-049**: Mean IOs MUST be the mean of per-query `n_ios` and MUST NOT be replaced with file
  sizes, estimated sectors, or operating-system counters.
- **FR-050**: SearchEvaluationReport/v1 MUST remain a separate Feature-local report unless planning
  proves that an existing report contract can be reused without semantic change.
- **FR-051**: Every SearchEvaluationReport MUST reference the SearchObservation,
  SearchProtocol/search execution, PQArtifact, DiskLayoutArtifact, Dataset, GlobalGraph, QuerySet,
  GroundTruth, evaluator identity/version, and pinned source mapping by immutable identity and
  checksum where applicable.
- **FR-052**: Evaluation MUST verify GroundTruth compatibility with Dataset, QuerySet, metric, and
  K; SearchObservation compatibility with `search_execution`; and evaluator compatibility with the
  declared evaluation policy.
- **FR-053**: The evaluator MUST independently derive `quality_eligible` and
  `performance_eligible` for every retained raw search point. Quality eligibility controls formal
  Recall@10/Recall@100 and their median and requires complete valid observations plus compatible
  Dataset, QuerySet, GroundTruth, SearchProtocol, evaluator, K/L, and result semantics, but not a
  normative performance environment. Performance eligibility controls formal K=100 QPS, mean
  latency, P99.9 latency, Mean IOs, and their median and additionally requires the declared Linux
  local-SSD/O_DIRECT/libaio and timing-boundary admission. Complete valid non-normative points MUST
  NOT enter formal performance aggregates. For every complete successful quality-eligible point,
  the existing Python Harness `evaluate` operation MUST compute and display QPS, mean latency,
  P99.9 latency, and Mean IOs from SearchObservation raw facts. Persisting those non-formal values in
  SearchEvaluationReport is optional; any persisted values MUST be classified
  `informational_non_formal`, with the specific exclusion recorded in
  `performance_eligibility_reason`. The report MUST still bind compatible GroundTruth, retain every
  excluded repetition, and preserve the existing Search Runner Parity scope.
- **FR-054**: Recall, QPS, latency, IO, or comparison findings MUST NOT be embedded in Dataset,
  GlobalGraph, PQ, DiskLayout, or BuildManifest data.
- **FR-055**: New metrics SHOULD be derived from already retained raw fields when possible; the MVP
  MUST NOT introduce a MetricPlugin, MetricRegistry, evaluator factory, or dynamic metric loader.

#### Parity, environment, failure, and optional comparison

- **FR-056**: The instrumented runner MUST pass a parity gate against the pinned upstream-faithful
  oracle under identical Dataset, search assets, QuerySet, K, L, beamwidth, threads, cache, IO, and
  control conditions before producing formal performance claims.
- **FR-057**: Parity MUST cover per-query ordered result IDs, declared-tolerance distances, Recall
  under identical GroundTruth, Mean IOs and core QueryStats semantics, QPS/latency formulas,
  canonical timing boundary, and exclusion of observation persistence from that boundary.
- **FR-058**: Parity MUST NOT require independent wall-clock QPS or latency values to be numerically
  identical; it verifies semantics, formulas, controls, and timing boundaries.
- **FR-059**: Formal QPS, latency, and Mean IOs claims MUST be restricted to a recorded Linux local-
  SSD environment that can establish pinned DiskANN disk-search IO semantics, including OS,
  filesystem, hardware, and storage placement.
- **FR-060**: macOS, Docker-on-macOS, remote storage, and other unproven IO environments MAY support
  schema, contract, parser, small functional, and non-normative correctness validation but MUST NOT
  produce formal performance claims.
- **FR-061**: Validation MUST use the existing Dataset and GlobalGraph validators and add only the
  necessary validators for newly produced post-graph products and source-verified compatibility;
  it MUST NOT copy, fork, or replace existing validation semantics.
- **FR-062**: Search or evaluation failure MUST use existing terminal semantics where applicable,
  retain available manifests/logs/diagnostic evidence, publish no fabricated complete output, and
  block evaluation, comparison, and aggregation as appropriate.
- **FR-063**: The optional multi-GlobalGraph comparison MUST use the same Dataset, byte-identical
  PQArtifact, QuerySet, GroundTruth, K, ordered L list, beamwidth, threads, cache, IO/warmup/timing,
  and formal environment while preserving an independent DiskLayout, graph identity, and that
  graph's own declared entry/medoid/centroid lineage per arm. The comparison MUST be labeled
  end-to-end and MUST NOT claim controlled-entry isolation.
- **FR-064**: Zero-cache and fixed-cache results MUST remain separate, and no valid, invalid,
  failed, slow, low-Recall, or otherwise eligible repetition may be silently discarded or replaced
  by a preferred result. All three declared repetitions remain auditable even when excluded from a
  median under the predeclared policy.
- **FR-065**: Multi-GlobalGraph comparison is optional and MUST NOT be a condition for MVP
  completion or be hard-coded specifically to M0/M1 in the reusable evaluator.
- **FR-066**: The Feature MUST NOT implement Query/Search backends beyond the pinned DiskANN path,
  dynamic/online indexing, disk PQ, reorder, filters, range search, cosine/MIPS, generic comparison,
  automatic tuning, SIFT100M+, or any new Vamana construction.

### Experiment Parameters Deferred to Research/Plan

The following implementation-environment parameters do not change the first-phase functional
scope. Research/Plan MUST resolve, record, and freeze them before any formal search execution:

- the formal ordered `L_search` list;
- fixed-cache target budget;
- formal thread count;

Source-observable facts such as actual input file formats, pinned fallback behavior, timing
implementation, distance tolerance, and native post-graph requirements are research questions, not
user preference questions.

### Key Entities

- **DatasetArtifact**: Existing immutable Dataset identity, native vector payload, dimensions,
  scalar type, metric compatibility, and checksum.
- **GlobalGraphArtifact**: Existing immutable GlobalNodeId adjacency, graph/medoid lineage, native
  payload, source identities, and aggregate checksum.
- **PQArtifact**: Dataset-derived reusable in-memory PQ search assets and their immutable payload
  identities; independent of GlobalGraph.
- **DiskLayoutArtifact**: Dataset-plus-GlobalGraph-derived disk-search layout bound to exactly one
  graph identity and that graph's own source-verifiable entry/medoid/centroid lineage under the
  end-to-end policy.
- **QuerySetReference**: For the first formal evaluation, the immutable identity of
  `sift1M_dataset/selected_query.csv`, including its location, format, size, count, dimension, and
  checksum. Query identity and row alignment use the zero-based `query_row_index` after the header;
  the CSV `id` is retained separately as an opaque `source_query_id` whose upstream meaning is not
  established and which has no Dataset GlobalNodeId semantics.
- **GroundTruthReference**: Immutable truth location, format, size, query count, width, and checksum;
  evaluation-only, width at least 100, and generated by exact L2 evaluation against the admitted
  SIFT1M Dataset.
- **SearchProtocol**: Frozen versioned declaration with separately identified search-execution and
  evaluation projections.
- **RawSearchPoint**: One independently retained `(L_search, repetition_index)` execution with its
  controls, completion status, batch time, and complete query observations; repetition index is one
  of the three predeclared attempts for its L and cache-specific protocol.
- **SearchObservation/v1**: Feature-local immutable collection of raw points plus search input,
  protocol, implementation, source, and build identities.
- **SearchEvaluationReport/v1**: Independent quality/performance report derived from a complete
  SearchObservation and compatible GroundTruth/evaluation policy.
- **BuildManifest**: Separate generation or execution provenance, toolchain, inputs, parameters,
  outputs, timestamps, resources, status, and failure reason.
- **ValidationEvidence**: Separate proof that a declared input or reusable output passed its
  applicable current validator.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A small verified GlobalGraph can be materialized into disk-search assets loadable by
  the pinned DiskANN path without any Partition, Local Build, Merge, or graph reconstruction.
- **SC-002**: The input GlobalGraph aggregate checksum is byte-for-byte identical before and after
  every successful materialization.
- **SC-003**: Every materialization run contains verifiable evidence that Partition, Local Build,
  and Merge invocation counts remained zero or an equivalent existing control-flow proof.
- **SC-004**: 100% of successfully published PQArtifacts validate independently and can be reused
  for later searches over the same Dataset identity.
- **SC-005**: 100% of successfully published DiskLayoutArtifacts bind exactly one Dataset and one
  GlobalGraph identity and pass all applicable native format, checksum, lineage, and loadability
  checks.
- **SC-006**: The pinned disk-search path successfully loads each valid MVP disk layout, PQ pivots,
  compressed vectors, and required entry/medoid metadata.
- **SC-007**: Every successful raw search point retains observations for 100% of declared queries;
  partial points are rejected from formal evaluation.
- **SC-008**: For each cache-specific protocol with `n` L values, exactly `n * 3` independently
  identified raw points, including retained terminal failures, are auditable without cross-point
  timing or observation ambiguity.
- **SC-009**: Recall@10 and Recall@100 can both be recomputed from the same top-100
  SearchObservation plus compatible GroundTruth, while K=100 QPS, mean latency, P99.9 latency, and
  Mean IOs can be recomputed from SearchObservation alone.
- **SC-010**: At least one additional aggregate metric supported by existing raw observation fields
  can be added without repeating SSD search.
- **SC-011**: The upstream-faithful oracle and instrumented runner pass ordered-result,
  distance-tolerance, Recall, QueryStats, formula, control, and timing-boundary parity before any
  instrumented formal-performance report is admitted.
- **SC-012**: Observation serialization, evidence writes, checksums, manifests, and evaluation are
  demonstrably excluded from 100% of canonical QPS timed regions.
- **SC-013**: 100% of runs lacking the declared Linux/local-SSD environment are labeled
  non-normative and cannot enter formal QPS, latency, or Mean IOs reporting.
- **SC-014**: Every formal report is traceable to the full DiskANN commit, project implementation,
  compiler/build flags, Dataset, GlobalGraph, PQ, DiskLayout, QuerySet, GroundTruth, SearchProtocol,
  hardware, OS, filesystem, and storage placement identities.
- **SC-015**: The fixed DiskANN gitlink and source tree remain unchanged and clean throughout all
  builds, tests, materializations, searches, and evaluations.
- **SC-016**: No experiment executed by this Feature exceeds SIFT1M, and no report claims support
  for a larger dataset.
- **SC-017**: 100% of first-phase formal SearchProtocols bind
  `sift1M_dataset/selected_query.csv` as the QuerySet and an exact-L2 GroundTruth generated against
  the same admitted SIFT1M Dataset identity.
- **SC-018**: 100% of first-phase formal QuerySet conversion, GroundTruth, search observation, and
  Recall paths use zero-based `query_row_index` for identity and row alignment, retain
  `selected_query.id` only as an opaque `source_query_id`, and perform no Dataset self-exclusion
  based on that value.
- **SC-019**: 100% of first-phase formal search points use K=100, retain exactly 100 ordered results
  per completed query, use only L values at least 100, and report Recall@10 and Recall@100 as
  separate metric identities.
- **SC-020**: 100% of formal DiskLayouts and optional comparison arms use and trace their input
  GlobalGraph's own source-verifiable entry/medoid/centroid policy and label the resulting
  evaluation as end-to-end.
- **SC-021**: Every formal L/cache search point attempts exactly three predeclared repetitions,
  retains all three outcomes, and reports separate per-repetition quality/performance eligibility
  plus separate medians over the repetitions eligible for each metric family, without
  result-dependent replacement or best-run selection.

## Assumptions

- Existing DatasetArtifact and GlobalGraphArtifact contracts, validators, BuildManifest,
  ValidationEvidence, and source-identity mechanisms are available for reuse.
- The pinned `cpp_main` Baseline and its commit-bound source mapping are available and remain
  read-only.
- The repository's existing `sift1M_dataset/selected_query.csv` is available as the only
  first-phase formal QuerySet; its exact-L2 GroundTruth will be generated and immutably bound to the
  admitted SIFT1M Dataset before formal evaluation.
- `selected_query.id` is preserved as an opaque `source_query_id`; repository evidence does not
  establish its upstream meaning, and the observed values are not the current CSV row ordinals.
  The Feature therefore uses zero-based `query_row_index` for query identity and row alignment and
  has no reliable Dataset GlobalNodeId mapping with which to perform Dataset self-match exclusion.
- First-phase formal GroundTruth has width at least 100; formal search retains top-100 and does not
  change K across repetitions, cache protocols, or compared GlobalGraphs.
- First-phase evaluation does not include a controlled-entry variant; any future addition of that
  policy requires a separate SearchProtocol and experiment classification rather than aggregation
  with end-to-end results.
- The predeclared quality/performance eligibility policies may exclude an invalid repetition from
  the applicable median but never from retained evidence; no extra execution replaces it, and a
  point with no eligible repetitions for one metric family has no formal aggregate for that family.
- At least one small native-format Dataset/GlobalGraph fixture and corresponding query/truth inputs
  can be prepared outside `upstream/` for independent User Story tests; those fixtures do not
  replace the selected formal QuerySet identity.
- Source audit will determine the exact supported scalar/native formats, entry/centroid fallback,
  timing boundary, distance tolerance, and safe post-graph materialization call path; the
  specification does not invent those facts.
- QuerySet and GroundTruth promotion to public Artifact types is deferred until more than one
  independent Feature demonstrates a shared need.
- Formal performance findings require a suitable Linux local-SSD host; development environments
  that cannot establish those semantics remain useful for non-normative correctness testing.
- Any future request above SIFT1M requires a separate explicit human approval and is outside this
  Feature.

## Explicit Non-Goals

- Modifying either the fixed DiskANN source or an input GlobalGraph.
- Rebuilding Vamana, Partition, Local Build, or Merge.
- Adding a fourth PipelineExecutor stage or a generic search/evaluation framework.
- Dynamic indexing, disk PQ, reorder, filtering, range search, cosine/MIPS, or automatic beamwidth.
- Parameter sweeps, optimization, automatic or changed-configuration retry, early stopping, or
  best-result selection.
- Public QuerySet/GroundTruth/SearchObservation Artifact families or a public metric/report plugin
  system.
- Generic multi-GlobalGraph comparison or M0/M1-specific behavior in a reusable evaluator.
- Controlled-entry evaluation in the first phase.
- SIFT100M or larger experiments.
