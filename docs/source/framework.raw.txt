1. 文档目标与技术边界

1.1 目标

  本项目的目标不是只复现某一篇论文，也不是只为某一次实验编写脚本，而是建立一套长期可扩展的
DiskANN 论文复现实验工程。该工程应支持在不覆盖原始实现的前提下，对 Partition、Build Local Graph
和 Merge Graph 等模块进行独立替换、耦合替换、跨论文组合和统一评估。

 保留并冻结原始 DiskANN Baseline。
 以稳定公共契约接入不同论文实现。
 保证不同实现可以复用阶段性产物，避免无条件全流程重跑。
 支持 Agent 根据 SDD、任务清单和反馈循环完成实现、验证与实验。
 支持单变量消融、强依赖组合和跨论文模块组合。

1.2 明确的代码基线

  本框架只以 Microsoft DiskANN 旧版 C++ cpp_main 分支为代码基线。所有 Baseline 结果、论文适配
和接口映射都必须绑定到一个固定 commit；不得使用“当前 cpp_main”作为不可追踪的浮动基线。

基线身份配置

  baseline:
    project: microsoft/DiskANN
    branch: cpp_main
    commit: <required-pinned-commit>
    language: C++
    target_pipeline: build_merged_vamana_index
    build_mode: static_offline_build
    source_modified: false


 强制要求：未记录 commit、编译参数、工作区修改状态和数据集校验值的运行，不得标记为有效 Baseline
 或有效论文复现结果。


1.3 研究范围

  第一阶段的核心研究范围是 cpp_main 中大规模内存受限 Vamana 构建路径的三个阶段：Partition、
Build Local Graph 和 Merge Graph。Search、Disk Layout、Memory Cache、Prefetch 与 I/O
Scheduling 可作为后续扩展阶段，但核心框架不能把模块分类永久限制为三个。

2. 三个核心模块的科学问题与定位

2.1 Partition

  为了解决的科学问题：在单机内存无法容纳全量向量数据及图构建中间状态的条件下，如何将大规模高
维向量数据划分为若干规模相对均衡、能够独立进行局部构图的子集，同时尽量保持原始数据中的近邻关
系，并控制重叠数据带来的额外存储、构建和合并开销。

  目的与作用：将全局构图转换为多个受内存预算约束的局部构图任务，为并行或分布式执行提供任务边
界；通过聚类、重叠分配、边界节点复制或论文特定策略，提高真实近邻共同出现在至少一个分块中的概
率。

  公共规范只要求 Partition 产物能够被下游消费，并提供完整的局部到全局节点映射。是否重叠、如何
选择边界点、是否输出质心和副本所有权，属于具体算法或可选能力。

2.2 Build Local Graph

  为了解决的科学问题：在每个分块只能获得局部数据与有限候选邻居的条件下，如何在出度、内存和构
建时间约束下生成高质量局部图，使其兼具局部近邻准确性、邻边多样性和有效导航能力，并为后续
Merge 提供可复用的局部拓扑。




                                          5

                                                             DiskANN cpp_main 论文复现实验框架 - 修订完整版

  目的与作用：独立构建各分块的局部图，保存局部邻接关系、局部入口点和 LocalNodeId 到
GlobalNodeId 的映射。原始 Baseline 使用 cpp_main 的 Index::build 和低出度参数；论文实现可以替换
候选生成、剪枝、插边、构图次序或整个局部图算法。

   单调性、特定剪枝定理、block-aware 性质等不应成为所有实现的统一接口约束，而应作为论文特定质
量验证。

2.3 Merge Graph

  为了解决的科学问题：在各分块局部图独立构建完成、同一全局节点可能以不同局部编号出现在多个重
叠分块中的条件下，如何正确完成局部节点到全局节点的映射，聚合同一全局节点在不同分块中的候选邻接
关系，并在不执行全量重新构图的前提下控制重复边、出度和中间状态开销，生成可在全量数据范围内统一
搜索的全局图。

    Baseline Merge 的目的：完成 LocalNodeId 到 GlobalNodeId 的转换，聚合同一全局节点在多个分块
中的局部邻接表，进行候选去重和出度控制，并输出全局编号空间下的图索引。

  增强型 Merge 的研究空间：论文实现可以增加跨分块候选发现、距离重计算、统一剪枝、全局
refinement、连通性检测与修复。这些是可选增强能力，不是 cpp_main 原始 merge_shards 已经提供的
功能。

 准确性边界：不得把“研究上希望 Merge 达到的能力”写成“原始 DiskANN Baseline Merge 的实际行
 为”。Baseline 语义必须与固定 commit 中的 merge_shards 一致。


3. 顶层设计原则与稳定不变量

3.1 与论文无关的稳定约束

 每个原始向量具有唯一且稳定的 GlobalNodeId。
 每个分块可以拥有独立、连续的 LocalNodeId 空间。
 每个局部产物必须提供完整的 LocalNodeId → GlobalNodeId 映射。
 同一 GlobalNodeId 可在多个重叠分块中拥有不同 LocalNodeId。
 最终全局图必须使用 GlobalNodeId 空间，且唯一逻辑节点数等于原始数据集节点数。
 每个阶段产物必须版本化、可校验、可追踪并可被独立复用。
 模块实现必须声明输入需求、输出能力和不支持的情况。
   Baseline 和论文方案的对比必须使用明确的公平性协议。

3.2 接口约束与算法实现分离

          核心规范应规定                    核心规范不应固定

 模块接收什么输入                   必须采用哪一种分块算法

 模块输出什么产物                   必须使用 RobustPrune

 节点编号与映射规则                  必须通过重叠节点建立跨块边

 哪些字段是必选或可选                 必须在 Merge 阶段执行连通性修复

 哪些结构不变量必须成立                必须满足某篇论文的单调性定义

 如何验证产物和结果                  必须以某一种文件布局实现


  这样可以同时兼容：不重叠分块、重叠分块、使用 kNN 图的分块、不同局部剪枝方法、无传统 Merge
的全局 refinement，以及同时修改多个阶段的论文。

3.3 原始代码不覆盖

    Baseline 和所有论文实现必须同时存在，通过 Registry 与实验配置选择实现。禁止以“复现下一篇论
文”为理由覆盖前一篇论文或原始 DiskANN 的代码。

  partition_impl: paper_a_partition
  local_build_impl: diskann_cpp_main_baseline
  merge_impl: paper_c_merge


  该原则用于保证可回退、可消融、可组合和可复现。

3.4 Baseline Parity Gate

  在任何论文替换实验开始前，必须验证“原生 cpp_main 命令直接运行”与“经统一
Pipeline/Adapter/Harness 运行”在统计意义上保持一致。

 节点数量、图文件可解析性、最大/平均出度。
 局部与全局入口点或 medoid。
  Recall、构建时间、峰值内存和查询性能。
 允许原始随机行为导致的波动，但不得存在系统性偏差。

6.1 三类编号

  using LocalNodeId  = uint32_t;
  using PartitionId  = uint32_t;

        编号                作用                约束

6.2 LocalToGlobalIdMap

  每个分块必须保存完整映射：

  LocalToGlobalIdMap[LocalNodeId] = GlobalNodeId


  局部图邻接表默认使用 LocalNodeId。Merge 通过 LocalToGlobalIdMap 将局部节点和局部邻居转换
为全局节点。该模型与 cpp_main 的 _ids_uint32.bin 语义一致。

6.3 重叠节点

  Partition 0: LocalNodeId 17 ─┐
                   ├─> GlobalNodeId 9245
  Partition 3: LocalNodeId 211 ─┘


  同一 GlobalNodeId 在不同分块中可以拥有不同 LocalNodeId。公共契约禁止将“相同全局节点必须
保留相同局部编号”作为要求。

6.4 编号相关硬不变量

  LocalToGlobalIdMap 的长度必须等于 local_node_count。
  LocalToGlobalIdMap 中每个值必须落入全局节点范围。
 局部邻接表中的每个邻居必须落入对应分块的 LocalNodeId 范围。
 最终全局图中不能残留 LocalNodeId 或未解析副本节点。
 最终唯一 GlobalNodeId 数量必须等于数据集节点数量。

11. cpp_main 原始 Baseline 的精确定义

11.1 Baseline 总流程

  当全量内存索引估算能够放入给定 RAM budget 时，build_merged_vamana_index 直接执行一次
Index::build。只有在全量图无法放入预算时，才进入分块构建和合并路径。

  if full_index_ram < ram_budget:
      IndexWriteParameters(L, R)
      Index::build(base_file)
      Index::save(mem_index_path)
  else:
      P0 = partition_with_ram_budget(...)
      B0 = Index::build(each shard, degree = 2R/3)
      M0 = merge_shards(..., max_degree = R)


   代码依据：microsoft/DiskANN,cpp_main,src/disk_utils.cpp，build_merged_vamana_index。

11.2 P0：Baseline Partition

  内存受限路径调用 partition_with_ram_budget，并将 graph_degree 传为 2R/3，将 k_base 传为
2。P0 生成分块 ID 文件和质心文件，随后框架根据每个 _ids_uint32.bin 从原始数据中提取 shard 数据。

  partition_with_ram_budget<T>(
      base_file,
      sampling_rate,
      ram_budget,
      2 * R / 3,
      merged_index_prefix,
      2              // k_base
  );


   代码依据：cpp_main/src/disk_utils.cpp，partition_with_ram_budget调用；cpp_main/include/partition.h，函数声明。

 注意：P0 的 “k_base=2” 是固定 commit 中的 Baseline 行为，不应被提升为所有论文 Partition 的公共要
 求。


11.3 B0：Baseline Local Build

  每个分块使用 IndexWriteParametersBuilder(L, 2R/3)，with_saturate_graph(false)，然后调用
Index::build 或 build_filtered_index，并保存为局部内存图。局部图使用 shard 内部的局部编号；对应
_ids_uint32.bin 提供局部到全局映射。

  IndexWriteParametersBuilder(L, 2 * R / 3)
      .with_filter_list_size(Lf)
      .with_saturate_graph(false)
      .with_num_threads(num_threads)
      .build();

  _index.build(shard_base_file, shard_base_pts);
  _index.save(shard_index_file);


   代码依据：cpp_main/src/disk_utils.cpp，分块循环与局部Index::build。

11.4 M0：Baseline Merge

   M0 的实际语义必须按照 merge_shards 描述：

 1. 读取每个 shard 的 LocalToGlobal ID map。
 2. 根据所有 ID map 计算全局节点数量，并建立 GlobalNodeId → shard 的反向关系。
 3. 读取并转换各 shard 的 medoid。

                                         18

                                                             DiskANN cpp_main 论文复现实验框架 - 修订完整版

 4. 对于同一 GlobalNodeId，读取其在所有相关 shard 中的局部邻接表。
 5. 通过 idmaps[shard][local_neighbor] 将局部邻居转换为全局邻居。
 6. 使用布尔集合去除重复候选邻居。
 7. 对候选集合执行随机打乱。
 8. 截断到 max_degree=R，并写入全局图。

  baseline_merge:
    candidate_source: union_of_replica_local_adjacencies
    id_conversion: local_to_global
    duplicate_removal: true
    candidate_distance_recomputation: false
    distance_based_pruning: false
    candidate_selection: random_shuffle_then_truncate
    connectivity_detection: false
    connectivity_repair: false
    output_id_space: global


   代码依据：cpp_main/src/disk_utils.cpp，merge_shards：read_idmap、node_shard、ID重命名、std::shuffle与
   max_degree截断。

 禁止误述：M0 不执行基于向量距离的统一 RobustPrune，也不显式检测或修复不可达子图。论文增强
 Merge 可以实现这些能力，但必须使用独立 implementation_id。

    Harness 是实验可信度的核心。Spec Kit 负责定义做什么，Harness 负责证明实现和实验是否满足规

16.2 Loop Engine 的职责

 生成和调度参数矩阵。
 复用已通过校验的上游 Artifact。
 对可重试失败进行受控重试。
 维护任务状态、检查点和依赖图。
 根据固定规则判断继续、终止或进入下一阶段。
 生成缺失实验清单和异常结果清单。

16.3 Loop 的安全边界

 禁止指标投机：Agent 不得通过降低 Recall、跳过查询、改变缓存状态、改变计时范围、只选择最优一次运
 行或偷偷修改参数来“优化”性能。所有停止与接受条件必须由 experiment-spec.md 和 Harness 校验器定
 义。



  loop:
    goal: complete_experiment_matrix
    retry:
      max_attempts: 2
      retry_on:
        - process_crash
        - incomplete_output
        - transient_io_error
    never_retry_on:
        - contract_violation
        - checksum_mismatch
        - incompatible_modules
    stop:
        - all_valid_runs_completed
        - unrecoverable_failure
        - resource_budget_exceeded


16.4 Agent 的人工闸门

  涉及算法语义修改时，Loop Engine 只能生成候选 patch 和实验建议。进入大数据实验前至少经过：
静态检查、单元测试、小图性质测试、SIFT1M 快速验证、人工审查 diff、再运行 SIFT100M 或更大数据

19. 完整验收清单与最终判断

19.1 核心 Pipeline 验收

 技术基线明确绑定 cpp_main 和固定 commit。
  GlobalNodeId、LocalNodeId、PartitionId 定义清晰。
 所有局部 Artifact 提供 LocalToGlobalIdMap。
   Artifact、BuildManifest、EvaluationReport 分离。
 模块通过 ArtifactRef 而不是全量内存对象传递。
   requires/provides 和格式版本在运行前校验。

19.2 Baseline 验收

  P0、B0、M0 的行为与固定 commit 源码一致。
  M0 被准确描述为映射、聚合、去重、shuffle 和 truncate。
 未将距离剪枝、全局 refinement 或连通性修复误写为原始行为。
  Upstream、Instrumented、Deterministic 三类 Baseline 独立标识。
 统一框架通过 Baseline Parity Gate。

19.3 论文复现验收

  论文与官方源码身份明确，commit 可追溯。
 算法步骤、官方源码和适配代码存在映射。
 复现类型和所有偏差明确记录。
 论文特定性质具有独立验证器。
 结论区分忠实复现、工程适配和性能优劣。

19.4 实验验收

 先完成 Baseline，再做单模块替换。
  固定参数与固定预算/Pareto 两类比较同时存在。
 每次运行有完整环境、配置、输入和输出记录。
 无效运行不会进入结果聚合。
 跨论文组合单独报告，不冒充单篇论文复现。

 最终判断：修订后的方案既保持了完整工程设计，又与 cpp_main 的实际行为一致。它能够支撑长期论文复
 现、独立模块替换、耦合方案、跨论文组合、Agent 自动实现与受控实验循环。
